# p-lens-brokers

> **この日本語版が原本です。** [English](README.md) は翻訳で、内容が食い違うときは日本語版に従います。

パチンコ・パチスロ店舗の特殊景品が、特殊景品交換所でいくらになったか。打ち手が実際に見た事実の記録です。JSON Lines 形式で [Open Database License](LICENSE) のもとに公開しています。

```text
data/observations.jsonl  観測の記録。1 行が 1 つの目撃
```

## これは何の記録か

ここにあるのはレート表ではありません。**観測者（パチンコ・パチスロを打つ人）が、その日に実際に見たこと**です。

> 2026 年 10 月 11 日、ある店舗の 4 円パチンコで、280 玉ぶんの特殊景品が、交換所で 1,000 円になった。

店舗も交換所も、この数字を公には言いません。だからここでは誰かの言い分としてではなく、その日そこでそうなった、という事実として 1 行ずつ積みます。
「この店はいくら」という答えは持ちません。読む人が、積まれた事実から読み取ります。

観測は、報告されたそのままが、誰も確かめないうちに載ります。間違いや、でたらめな行も混じります。
それも含めて記録です。ある行が信じられるかどうかは、同じ店舗のほかの行、同じ観測者（`observer`）のほかの行と並べて、読む人が判断してください。

## 名前について

broker（ブローカー）は仲買人、人から渡されたものを扱って、あいだに立つ者のことです。ここでは特殊景品交換所をこう呼びます。
「prize exchange」と呼ばないのは、P-Lens ではそれが店舗のすること（交換払出：玉・メダルを景品と交換すること）を指すからです。

## なぜ別のリポジトリなのか

店舗は玉・メダルを貸し、特殊景品と交換するだけで、お金とは交換しません。特殊景品を買い取るのは、店舗とは別の特殊景品交換所（以下、交換所）です。
店舗と交換所は別のものなので、データも別のリポジトリに置いています。

- 店舗の一覧と、店舗ごとのコーナー・レート（貸し、再プレイ、特殊景品の種類ごとに要る玉数・枚数）は [p-lens-parlors](https://github.com/p-lens/p-lens-parlors)。店舗が掲げている内容で、円は出てきません
- 交換所で実際にいくらになったかの観測はここ

2 つは店舗の `id` だけでつながっています。どちらかを消しても、もう一方には何も起きません。
app.p-lens.jp はこのリポジトリを読みません。

## 形式

1 行が 1 つの観測です。同じ店舗、同じ日の観測がいくつあってもかまいません。
観測には 2 種類あります。特殊景品が交換所でいくらになったかの行と、交換所の名前だけの行です。

```json
{"parlor":"osm:way/…","observedOn":"2026-10-11","game":"pachinko","tier":"4円","prize":"小景品","tokens":280,"yen":1000,"submission":"…","observer":"…"}
{"parlor":"osm:way/…","observedOn":"2026-10-11","broker":"(一社)…","submission":"…","observer":"…"}
```

名前だけの行は、観測者が額は見ていないが、その店舗の特殊景品を買い取る交換所の名前を見た、という観測です。`game`、`tier`、`prize`、`tokens`、`yen` を持たず、`broker` を必ず持ちます。

| 項目 | | |
|---|---|---|
| `parlor` | 必ず | 特殊景品を受け取った店舗。p-lens-parlors の `parlors.jsonl` か `unplaced.jsonl` にある `id` |
| `observedOn` | 必ず | 観測者がそれを見た日（YYYY-MM-DD）。実際に見たことなので、先の日付はありません |
| `broker` | 名前だけの行では必ず、ほかは任意 | 特殊景品を買い取った交換所の名前。観測者が名前を入れたときだけあります。名前のない交換所が多いので、額の行ではない行がふつうです |
| `game` | 額の行では必ず | `pachinko` か `pachislot` |
| `tier` | 額の行では必ず | コーナー。店舗が掲げているレート（`4円`、`1円`、`20円`、`5円` など） |
| `prize` | 額の行で `tokens` がなければ必ず | 特殊景品の名前（`大景品`、`小景品` など、店舗での呼び方） |
| `tokens` | 額の行で `prize` がなければ必ず | その特殊景品を受け取るのに店舗で要った玉数・枚数 |
| `yen` | 額の行では必ず | 交換所がその特殊景品に払った額（円） |
| `submission` | 必ず | この観測が報告された survey.p-lens.jp の報告の ID。同じ報告に店舗のことも書かれていれば、p-lens-parlors の issue に同じ ID があります |
| `observer` | 必ず | 観測者。観測者の端末が自分で作った仮名（UUID）で、人の名前ではありません。同じ観測者の観測は、同じ仮名で並びます |

交換できる最小の単位（500 円から、1,000 円から、など）は、観測のなかでいちばん小さい `yen` から読み取れます。
数字が変わったら、変わったあとの観測が新しい行として積まれます。前の行は、その日にそうだったという記録としてそのまま残ります。

`parlor` が店舗一覧にあるかどうかは、ここでは確かめません。2 つのリポジトリは互いを読まないからです。
一覧からなくなった店舗の観測は、両方を合わせて読む側が読み飛ばします。

## データの出どころ

survey.p-lens.jp で受け付ける報告だけに拠ります。観測者本人が現地で見たこととして報告され、投稿者が CC0 で提供したものです。
survey.p-lens.jp は、出典が「現地で確認した」で、日付が先でない報告だけを受け付け、形式を確かめたうえでそのまま載せます。内容が本当かどうかは確かめていません。
人から聞いた話、これから変わるらしいという話、店舗ポータルサイト、Google マップなどの地図サービス、そのほかのサイトやデータベースから写したものは、報告しない約束になっています。

## 確かめ方

```sh
bun install
bun run check
```

## 公開のしかた

`main` に入ったものが、そのまま brokers.p-lens.jp に出ます。Cloudflare がこのリポジトリを見ていて、`main` が進むたびに `bun run check` を走らせ、通れば `data/` を公開します。

```text
Cloudflare の設定（Workers ＞ このリポジトリを接続）
  ビルドの命令      bun install && bun run check
  デプロイの命令    bunx wrangler deploy
  ビルドの変数      BUN_VERSION=1.4.2
```

何をどこに出すかは `wrangler.jsonc` に、ファイルと一緒に送るヘッダーは `data/_headers` に、brokers.p-lens.jp を開いた人に見せる案内は `data/index.html` にあります。

## 観測が載るまで

観測は、survey.p-lens.jp の店舗の報告のうち「特殊景品」の行（交換所で受け取った額のあるもの）と、交換所名です。額のある行がない報告の交換所名は、名前だけの 1 行になります。

- **一覧にある店舗の観測** は、報告を受け付けた時点で survey.p-lens.jp が `data/observations.jsonl` の末尾に 1 行ずつ足し、そのまま公開されます。人は間に入りません
- **一覧にまだない店舗の観測** は、店舗の `id` がまだないので行にできません。このリポジトリの issue（ラベルは `survey`、`broker`、`add`）になります。その店舗が p-lens-parlors の一覧に載ったら、issue の内容を、店舗の `id` を `parlor`、報告の ID を `submission` として手で 1 行ずつ（交換所名だけなら名前だけの 1 行を）足します

同じ報告の、店舗が掲げている内容（コーナー、貸し、再プレイ、景品に要る玉数・枚数）は p-lens-parlors の issue になり、そちらには円は載りません。

すでにある行は書き換えません。でたらめな行を取り除くときは、その行を消すコミットを `main` に入れます。`observer` が同じ行をまとめて消すこともできます。

survey.p-lens.jp が足す行は、`bun run check` に通るものだけです。通らない行が入ると公開が止まるので、形式を変えるときは、先に survey.p-lens.jp を合わせます。

このリポジトリには、ラベル `survey`、`broker`、`add` を作っておきます。行を足すのは、このリポジトリのためだけに作った GitHub App です。survey.p-lens.jp が店舗一覧の issue を建てるのに使う App とは別のもので、このリポジトリにだけ入れ、**Contents**（行を足すため）と **Issues**（一覧にない店舗の観測のため）の読み書きを許します。
