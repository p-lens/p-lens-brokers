# p-lens-brokers

> **この日本語版が原本です。** [English](README.md) は翻訳で、内容が食い違うときは日本語版に従います。

パチンコ・パチスロ店舗の特殊景品が、特殊景品交換所でいくらになったか。打ち手が実際に見た事実の記録です。JSON Lines 形式で [Open Database License](LICENSE) のもとに公開しています。

```text
data/observations.jsonl  観測の記録。1 行が 1 つの目撃
```

## これは何の記録か

ここにあるのはレート表ではありません。**観測者（パチンコ・パチスロを打つ人）が、その日に実際に見たこと**です。

> 2026 年 10 月 11 日、ある店舗の 4 円パチンコで、280 玉ぶんの特殊景品が、交換所で 1,000 円になった。

店舗も交換所も、この数字を公には言いません。だからここでは誰かの言い分としてではなく、その日そこでそうなった、という事実として 1 行ずつ積みます。
「この店はいくら」という答えは持ちません。読む人が、積まれた事実から読み取ります。

## 名前について

broker（ブローカー）は仲買人、人から渡されたものを扱って、あいだに立つ者のことです。ここでは特殊景品交換所をこう呼びます。
「prize exchange」と呼ばないのは、P-Lens ではそれが店舗のすること（交換払出：玉・メダルを景品と交換すること）を指すからです。

## なぜ別のリポジトリなのか

店舗は玉・メダルを貸し、特殊景品と交換するだけで、お金とは交換しません。特殊景品を買い取るのは、店舗とは別の特殊景品交換所（以下、交換所）です。
店舗と交換所は別のものなので、データも別のリポジトリに置いています。

- 店舗の一覧と、店舗ごとのコーナー・レート（貸し、再プレイ、特殊景品の種類ごとに要る玉数・枚数）は [p-lens-parlors](https://github.com/p-lens/p-lens-parlors)。店舗が掲げている内容で、円は出てきません
- 交換所で実際にいくらになったかの観測はここ

2 つは店舗の `id` だけでつながっています。どちらかを消しても、もう一方には何も起きません。
app.p-lens.jp はこのリポジトリを読みません。

## 形式

1 行が 1 つの観測です。同じ店舗、同じ日の観測がいくつあってもかまいません。

```json
{"parlor":"osm:way/…","observedOn":"2026-10-11","broker":"交換所","game":"pachinko","tier":"4円","prize":"小景品","tokens":280,"yen":1000,"submission":"…"}
```

| 項目 | | |
|---|---|---|
| `parlor` | 必ず | 特殊景品を受け取った店舗。p-lens-parlors の `parlors.jsonl` か `unplaced.jsonl` にある `id` |
| `observedOn` | 必ず | 観測者がそれを見た日（YYYY-MM-DD）。実際に見たことなので、先の日付はありません |
| `broker` | 必ず | 特殊景品を買い取った交換所の名前。分からなければ `交換所` |
| `game` | 必ず | `pachinko` か `pachislot` |
| `tier` | 必ず | コーナー。店舗が掲げているレート（`4円`、`1円`、`20円`、`5円` など） |
| `prize` | `tokens` がなければ必ず | 特殊景品の名前（`大景品`、`小景品` など、店舗での呼び方） |
| `tokens` | `prize` がなければ必ず | その特殊景品を受け取るのに店舗で要った玉数・枚数 |
| `yen` | 必ず | 交換所がその特殊景品に払った額（円） |
| `submission` | 必ず | この観測が報告された survey.p-lens.jp の報告。観測者は、その報告の記録に端末ごとの仮名で残っています。人の名前ではありません |

交換できる最小の単位（500 円から、1,000 円から、など）は、観測のなかでいちばん小さい `yen` から読み取れます。
数字が変わったら、変わったあとの観測が新しい行として積まれます。前の行は、その日にそうだったという記録としてそのまま残ります。

`parlor` が店舗一覧にあるかどうかは、ここでは確かめません。2 つのリポジトリは互いを読まないからです。
一覧からなくなった店舗の観測は、両方を合わせて読む側が読み飛ばします。

## データの出どころ

survey.p-lens.jp で受け付ける報告だけに拠ります。観測者本人が現地で見た一次情報で、投稿者が CC0 で提供し、取り込む前に確認しています。
人から聞いた話、これから変わるらしいという話、店舗ポータルサイト、Google マップなどの地図サービス、そのほかのサイトやデータベースからは、何も採っていません。

**「© P-Lens contributors」** と表示し、このデータベースから派生したデータベースは ODbL のもとに置いてください。

## 確かめ方

```sh
bun install
bun run check
```

## 公開のしかた

`main` に入ったものが、そのまま brokers.p-lens.jp に出ます。Cloudflare がこのリポジトリを見ていて、`main` が進むたびに `bun run check` を走らせ、通れば `data/` を公開します。

```text
Cloudflare の設定（Workers ＞ このリポジトリを接続）
  ビルドの命令      bun install && bun run check
  デプロイの命令    bunx wrangler deploy
  ビルドの変数      BUN_VERSION=1.4.2
```

何をどこに出すかは `wrangler.jsonc` に、ファイルと一緒に送るヘッダーは `data/_headers` に、brokers.p-lens.jp を開いた人に見せる案内は `data/index.html` にあります。

## 報告を取り込む

観測は、survey.p-lens.jp の店舗の報告のうち「特殊景品」の行（交換所で受け取った額のあるもの）として、p-lens-parlors の issue に届きます。

1. p-lens-parlors の issue を読み、出どころと内容を確かめる。出典が「現地で確認した」で、「確認した日」が先の日付でない報告だけを取る
2. `data/observations.jsonl` に、額のある行ごとに 1 行足す。店舗の `id` を `parlor`、報告の「確認した日」を `observedOn`、報告の ID を `submission` とし、種別はパチンコを `pachinko`、パチスロを `pachislot`、レート 4 は `4円` と書く。「特殊景品交換所の名前」がなければ `broker` は `交換所`
3. `bun run check`
4. `main` に入れる。すでにある行は書き換えない
